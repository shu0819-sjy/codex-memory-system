# 跨平台文件型记忆系统设计

日期：2026-10-06
状态：待用户审阅
仓库基线：`main`，版本 `0.1.0`

目标版本：`0.2.0`

## 目标

将当前以 Windows PowerShell 为中心的模板，完善为 Windows、macOS 和 Linux 均可安装、配置、自检和维护的文件型记忆系统。新用户能通过清晰的入口完成安装和接入；现有用户升级时不会丢失个人记忆；记忆结构规则易配置且可验证。

## 当前基线

- `install.ps1` 负责 Windows 安装，目标目录存在时默认停止，`-Force` 会先备份再替换。
- `memory/check-memory.ps1` 检查固定的中文分类、文件大小、编码、日期格式、重复条目、进行中任务和归档命名。
- GitHub Actions 仅在 `windows-latest` 运行。
- 仓库有安装说明、安全边界和模板数据，但没有独立的自动化测试目录。

## 方案

采用 Python 标准库作为唯一跨平台核心，避免维护三份安装和检查逻辑。最低支持 Python 3.11；CI 在 3.11、3.12、3.13、3.14 上验证。工具代码留在用户克隆的仓库中，目标安装目录只保存个人记忆、分类、归档和本地配置；用户可在仓库目录通过 `python -m codex_memory` 调用核心命令。Windows、macOS、Linux 各提供轻量启动入口，负责定位 Python 并传入参数。初版不引入第三方运行依赖。

核心命令：

- `install`：首次安装、交互配置和安全更新记忆模板。
- `check`：只读检查当前记忆目录并输出可定位的问题。
- `instructions`：打印可复制到用户 `AGENTS.md` 的接入片段，不直接修改该文件。

默认安装位置延续现有约定：用户主目录下的 `.codex-memory`；用户可以通过参数指定其他目录。命令同时支持交互模式和明确参数驱动的非交互模式，以便人工安装与自动化脚本复用同一逻辑。README 将提供克隆一次后的各平台入口命令；后续工具更新通过拉取仓库更新代码，再运行安全模板更新命令完成。

## 安装、配置与迁移

1. 目标目录不存在时，安装完整记忆模板，并生成不含个人路径或密钥的本地配置文件。
2. 目标目录已存在时，默认拒绝覆盖并给出下一步选项。
3. `--update` 从当前仓库模板补入目标目录缺失的文件，并更新模板版本元数据；已有记忆正文、分类文件、规则、配置和归档一律保留。工具代码不复制到目标目录，也不由该命令更新；新版本新增模板文件仅在目标缺少时补入，不覆盖已有同名文件。
4. 更新发生路径冲突或写入失败时，先保留备份，再回滚本次修改；输出备份位置和恢复结果。
5. 不提供“无备份强制覆盖”路径。旧版 `-Force` 的整目录替换语义不延续；README 明确说明新版安装/更新命令及从 `0.1.0` 升级方式。升级用户保留原安装目录，克隆新版仓库后运行更新命令。
6. 配置仅保存安装目录、分类清单、检查阈值和隐私扫描选项；不存储令牌、密钥或对话内容。配置格式使用 JSON，避免第三方解析依赖。配置按不可信输入校验：分类名只能是单一文件名，拒绝空值、`.`、`..`、路径分隔符及控制字符；未知键、错误类型和无效阈值报清晰错误，不回显配置内容。

## 记忆结构与自检

将当前固定在 PowerShell 脚本中的检查逻辑迁移到 Python，并把可变化规则移入配置。检查器负责验证：

- 热记忆入口、规则文件、分类目录和归档目录存在；
- 热记忆索引引用的分类与配置清单一致，引用文件确实存在；
- 文件大小、UTF-8 编码、日期和条目格式符合配置；
- 进行中事项数量、日期新鲜度及重复条目符合规则；
- 归档文件名符合命名约定；
- 仓库模板中没有已配置的个人路径、敏感词模式或疑似凭据。
- 检查结果只显示命中文件和行号，不输出记忆正文或匹配到的敏感文本。

检查必须只读，不自动修复或重排用户文件。输出按 `PASS`、`WARN`、`FAIL` 分类，指出文件和行号；无失败返回 `0`，检查发现失败返回 `1`，命令参数或配置不可用返回 `2`。

## 测试与持续集成

- 使用 Python 标准库 `unittest`，不要求安装测试框架。
- 覆盖首次安装、拒绝覆盖、更新保留记忆、缺失模板补入、写入失败回滚、只读检查、配置错误和退出码。
- 路径用例覆盖含空格、中文和非默认主目录；平台专属路径行为在对应 runner 上验证。
- GitHub Actions 覆盖 Windows、macOS、Linux，并在 Python 3.11、3.12、3.13、3.14 上运行单元测试、语法检查、自检和公开模板隐私扫描。
- CI 只在临时目录执行安装测试，不触碰 runner 上的真实用户目录。

## 文档与发布

- README 首屏提供项目用途、平台支持、前置条件、最短安装流程和分享/安全边界。
- 分别列出 Windows、macOS、Linux 命令；补充交互与非交互安装、指定目录、检查、更新和恢复说明。
- 提供中英双语安装指南，避免平台命令只写在单一语言文档中。
- 更新 `CHANGELOG.md` 和 `VERSION`；发布检查涵盖跨平台 CI、全新安装、旧版升级、隐私扫描和许可证。
- 仓库不自动发布 Release，不推送提交或更改 GitHub 仓库设置；这些属于本地实现之后的单独发布动作。

## 安全与非目标

- 不读取、上传或自动写入聊天内容；不启用数据库记忆、同步服务或后台常驻进程。
- 不自动编辑用户 `AGENTS.md`、Codex 配置、权限、模型或网络设置。
- 不在公开模板中提交个人记忆、日志、密钥或机器绝对路径。
- 安装拒绝跟随模板源中的符号链接；安全更新在修改前检查目标内部路径，不沿目标目录中的符号链接写入。
- 不实现云同步、账号体系、GUI 或自动执行生成的接入指令。

## 验收标准

1. 在 Windows、macOS、Linux 的 CI runner 上，安装器和自检器均通过同一套核心测试。
2. 新目录安装后，生成完整且可通过自检的记忆结构；交互和非交互路径均有测试。
3. 对已存在的目录，默认安装不会改动任何文件；更新不会覆盖用户记忆、规则、分类内容或归档。
4. 模拟更新失败时，原始用户文件仍可恢复，命令报告备份位置和失败原因。
5. 修改配置可以新增或改名分类与阈值，不需要编辑检查器源代码；索引和文件不匹配时可定位报告。
6. 三个平台 README 步骤与 CI 中实际执行的入口一致，且不要求第三方 Python 包。
7. 公开仓库扫描通过，仓库中无个人数据、密钥或本机绝对路径。

## 实施切分建议

1. Python 包、配置模型和只读检查器；先以测试固定现有检查行为，再增加配置驱动规则。
2. 跨平台安全安装与升级，保留 `0.1.0` 用户数据并验证失败回滚。
3. Windows/macOS/Linux 启动入口与三平台 CI。
4. README、接入说明、版本记录和发布前检查清单。

每一阶段都以测试通过和用户数据保留验证为验收门槛。Python 最低版本定为 3.11；[Python Developer's Guide: Status of Python versions](https://devguide.python.org/versions/) 将 3.11 至 3.14 列为受支持版本，并将 3.10 标记为 2026-10-01 结束支持。CI 验证三种操作系统与四个 Python 版本的组合，并在 README 与工作流中保持一致。目标版本为 `0.2.0`。
